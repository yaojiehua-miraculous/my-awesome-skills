# examples/ —— 黄金示例

> **在创建任何新技能之前，请务必先读本目录。** 一份示例胜过一千字规则说明。

AI 生成技能时最容易跑偏的三件事：把技能写成文章、把调度写成亲自干活、把敏感信息写进公开区。
这三份示例就是这三类跑偏的反面教材 + 标准答案。

| 文件 | 解决什么跑偏 | 读它的时候看什么 |
|---|---|---|
| [`01-golden-skill.md`](01-golden-skill.md) | 技能写成了功能介绍 | frontmatter 怎么填、正文五段怎么写、结尾那张"不合格写法对照表" |
| [`02-orchestrator-demo.md`](02-orchestrator-demo.md) | 指挥人亲自下场干活 | 内部六步思考、对外第一段【路由】结论长什么样 |
| [`03-forge-demo.md`](03-forge-demo.md) | 归档时把敏感信息写进仓库 | 脱敏映射表怎么用、查重怎么拦住"又一种成因" |

## 使用方式

```
README + 01  →  我要写/改一个技能
02           →  我要确认调度逻辑没跑偏
03           →  我要把一次对话归档成技能
```

## 两条纪律

1. **示例是公开内容**，发布前和 `skills/` 一起过第二道人工清洗（见 `docs/RELEASE.md`）。
2. 示例里出现的公司名、域名、密钥、IP、批次号**全部是伪造的**，只为演示格式。
   如果你拿真实会话来补示例，先跑 `python scripts/desensitize.py --fix examples/`。

示例文件里若出现 `<!-- desensitize:allow-fake-secrets ... -->` 豁免注释，那是给"故意演示脏数据"用的；
这条豁免在 `skills/` 下会被脚本判为失败——防止以后图省事给真实资产开豁免。
