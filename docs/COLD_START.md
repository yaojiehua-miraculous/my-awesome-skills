# 冷启动

目标：**五分钟内，从"什么都没有"到"一个能用的助手"，且不烧 token。**

冷启动不是装完所有技能。装得多，启动就慢、路由就飘、注意力就散。这里只做三件事。

## 第一步：三个问题

装好之后，不要立刻派活。先让助手问你三个问题（或者你自己回答），用来决定装载哪一档：

```
Q1 你主要做什么活？（前端 / 后端 / 数据 / 运维 / 混合）
Q2 你现在手上这件事，属于"改代码"还是"查故障"？
Q3 这个项目是新的，还是已经跑了一段时间的老项目？
```

三问的价值不在答案本身，而在于**把"用户是谁"变成"该装什么"**：

| 答案组合 | 最小装载 |
|---|---|
| 后端 + 查故障 + 老项目 | `api-error-triage`、`docker-runtime-troubleshoot` |
| 后端 + 改代码 + 任何 | `unit-test-first`、`code-review-two-tier` |
| 任何 + 要提交 | `commit-message` |
| 混合 + 复杂需求 | 先只装 `master-orchestrator`，其余按需 |

## 第二步：最小装载原则

- **只装 2–3 个种子技能**，不要一次装 5 个。
- 指挥人（`master-orchestrator`）建议常驻——它是唯一需要"每轮在场"的技能。
- 其余技能**不装也能用**：`mount.py` 可以只挂指定目录（`--only`），不挂的就不进菜单。

装完跑一次：

```bash
python scripts/scan_skills.py --menu      # 刷新 L0 菜单
python scripts/mount.py --only master-orchestrator --only api-error-triage
```

菜单开销应该在 30 token 以内——这比"装 50 个技能"便宜两个数量级，效果却不会差，
因为你要解决的多半就是那一两类问题。

## 第三步：第一次真正使用

用一句**模糊的真实请求**去试，不要用精心构造的 prompt：

```
线上支付好像挂了，帮我看看
```

验收标准只有一条：**第一段是不是【路由】结论**。

- 是 → 挂载成功，纪律生效，继续用。
- 不是（直接甩代码）→ `AGENTS.md` 或指挥人没被读到。先修挂载，别急着调提示词。

## 三个常见冷启动故障

| 现象 | 原因 | 处理 |
|---|---|---|
| 助手完全看不到技能 | 宿主不扫这个目录 | 换 `--dest`，或 `--user` 挂到用户级 |
| 看到了但不触发 | `description` 写成了功能介绍 | 改成"当……时触发"，重跑 `--menu` |
| 触发了但没按五段执行 | 只读到摘要没读到正文 | 让助手显式 `Skill("<name>")` 一次，确认正文可达 |

## 不要做的事

- 不要一次装 5 个以上技能来"试试看"。
- 不要为了"完整"先写 `personal/` —— 空目录是对的，它要靠使用长出来。
- 不要在冷启动阶段调优 `trigger` 关键词——先跑三天，看真实命中情况再调。
