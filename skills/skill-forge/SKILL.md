# 采集沉淀（Forge）

把"这次怎么解决的"变成"下次自动这么做"。你不是在写文档，你是在给未来的自己写一条操作系统指令。

## 适用 / 不适用

**适用**
- 一个问题花了 3 轮以上才解决，且答案可复述。
- 用户明确说"记一下""沉淀成技能""下次别再踩"。
- 指挥人判定为 P2 且已成功收尾。

**不适用**
- 一次性的环境故障、别人的代码库八卦、纯闲聊。
- 结论还没验证（"应该可以""可能是"）——猜出来的东西不许入库。
- 已有同族技能且本次没有新增信息（此时正确的动作是**什么都不做**）。

## 步骤

**Step 1 判断值不值得**
问三个问题，任一为否就放弃归档：
1. 这个问题下次还会出现吗？
2. 解决步骤能写成可执行的顺序吗？
3. 换个项目、换个时间，这些步骤还成立吗（去掉项目特有细节后）？

**Step 2 三字段压缩**
只保留三样东西，其余全部丢弃：
- **痛点**：什么现象、什么条件下触发（可观测的报错原文或症状）。
- **方案**：按顺序的步骤，每步有可验证的中间结果。
- **坑**：试过但没用的路，以及为什么没用。

**Step 3 强制脱敏**（不可跳过，不可"我觉得没有敏感信息"）
按顺序替换，替换不进正文就不要写这条技能：

| 类型 | 替换为 |
|---|---|
| 客户名 / 公司名 / 内部系统名 | `<CUSTOMER>` / `<SYSTEM>` |
| 内网域名、内网 IP、端口 | `<HOST>` / `<IP>` / `<PORT>` |
| 令牌、Cookie、签名、AK/SK | `<SECRET>` |
| 本地绝对路径 | `<PATH>` |
| 真实订单号 / 批次号 / 手机号 | `<ID>` / `<PHONE>` |

替换后跑一遍：`python scripts/desensitize.py --check personal/`，必须 0 命中。

**Step 4 查重**（最关键的一步，也是最容易偷懒的一步）
1. 在菜单里找同 `domain` 的技能名。
2. 打开最像的那一个，比对「痛点」是否同族。
3. 判定：
   - 同一族、只多了一种成因 → **不新建**，给原技能加一节，`version` 升次版本号（`1.0.0` → `1.1.0`）。
   - 同一族、但触发条件完全不同 → 可以新建，`domain` 保持一致。
   - 不同域 → 新建。
4. 该 `domain` 下已有 ≥ 5 个技能 → **禁止新建**，必须先合并同类项。

**Step 5 落盘**
- 位置：`personal/<kebab-name>/SKILL.md`。
- `scope` 一律 `personal`，`type` 按内容选 `flow` / `domain` / `role`。
- 正文严格五段：适用/不适用、步骤、检查清单、跑偏信号、产出。
- `trigger` 写用户真实会说的话（"报错""超时""对不上"），不要写术语堆。

**Step 6 回读确认**
写完立刻读回该文件，确认：
- frontmatter 十个字段齐全；
- 正文里没有残留真实名称、IP、路径、密钥；
- 五段标题都在。

**Step 7 刷新菜单**
跑 `python scripts/scan_skills.py --menu`，否则新技能不会被路由到。

## 检查清单

- [ ] 三个"值不值得"问题都是"是"。
- [ ] 只有痛点 / 方案 / 坑三块，没有背景铺垫和客套话。
- [ ] 脱敏检查 0 命中。
- [ ] 查重做过了，且写下了"为什么不新建"或"为什么新建"。
- [ ] `scope: personal`，路径在 `personal/` 下。
- [ ] 回读过文件，菜单已刷新。

## 跑偏信号

1. 把整段对话复制进 SKILL.md（那不是技能，是日志）。
2. 保留真实客户名、内网域名、真实批次号——最严重的一种。
3. 同一类报错，第三次还新建文件（技能库膨胀成了垃圾场）。
4. 写成了"背景介绍 + 思考过程 + 总结"，没有可执行步骤。
5. 归档了没验证的猜测。
6. 写进 `skills/`（公开区）而不是 `personal/`（私有区）。

## 产出

1. 一个新文件 `personal/<name>/SKILL.md`，或一次版本升级。
2. 一句归档说明：`归档 <name> v<新版本> ← 痛点一句话`（或 `不新建，合并进 <已有技能>`）。
3. 刷新后的菜单 token 开销（由 `scan_skills.py` 打印）。
